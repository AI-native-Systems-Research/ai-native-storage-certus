10Candidates listed in eviction orderget_eviction_candidates, identify_next_to_evictThe candidates are listed in the order the policy would actually evict them, oldest access first, so the first candidate in the list is exactly the block a victim request would return at that moment, the second is the one after that, and so on.Beyond its first entry, the candidate list is not in general the order in which blocks will actually be evicted. Evicting a block can promote its ancestor into the candidate set at that ancestor's older recency, and the promoted ancestor can then be evicted ahead of blocks that the earlier list named. For example, with one session holding an older block beneath a newer one and a second session holding a single newest block, the list of two candidates names the newer block of the first session and then the block of the second session, whereas two successive evictions take the newer block of the first session and then its promoted ancestor.
