`initialize_from_client` is an intended FR-17 wiring API and may remain inherent;
narrow FR-011's "operations it validates" to the put/get/delete/iterate_all
operations plus durability. Do **not** modify component source; only the test and

## Task: Align 002-ssd-integration-test/FR-007 — surface capacity exhaustion to the caller  [ALIGN-EMS-002]

**Severity**: moderate

**Spec Requirement**: 002 spec FR-007 / User Story 5 scenario 2 / Capacity note —
capacity exhaustion must be surfaced to the caller; `test_capacity_exhaustion`
(`tests/integration_ssd.rs:526-547`, `CapacityExhausted` arm at `:542`) expects an
`ExtendedMetadataStoreError::CapacityExhausted` result. The interface defines the
variant for exactly this purpose (`../interfaces/src/iextended_metadata_store.rs:12`).

**Current Code**: `put()` enforces only the 128 KiB per-value `ValueTooLarge`
limit (`src/lib.rs:179`). Region/partition capacity is enforced solely at flush
time inside `flush::flush_to_disk` as a `String` error ("exceeds region
capacity", `src/flush.rs:36-42`) and is never mapped to
`ExtendedMetadataStoreError::CapacityExhausted` on any interface method.
Consequently `CapacityExhausted` is never constructed and
`test_capacity_exhaustion` loops to `max_attempts` without ever reaching the
`Err(CapacityExhausted)` branch — it passes trivially.

**Required Change**: Surface capacity exhaustion to the caller through the
interface as `CapacityExhausted`. Preferred approach: have `put()` (or a
capacity-aware interface method) detect that the aggregate serialized region
would exceed `Superblock::region_capacity_bytes()` (`src/on_disk.rs:147`) and
return `Err(ExtendedMetadataStoreError::CapacityExhausted)`; alternatively map the
flush-time `String` capacity error to `CapacityExhausted` and propagate it out of
`force_flush()`. Do **not** relax the spec to flush-time-only enforcement. Do
**not** modify source in this sweep — this task is queued for implementation.

**Status (refreshed 2026-10-14, proposal P6):** still open and **parked** (maintainer
decision 2026-09-03). The variant is still never constructed. **Dependency:** ALIGN-EMS-003 has landed (`4a8fe3e7`): the flush-time capacity error now reaches `force_flush()` callers as `StorageError("… exceeds region capacity …")`. The alternative fix only needs to map it to `CapacityExhausted`. The preferred
`put()`-time check does not depend on ALIGN-EMS-003.

**Files to Modify**:
- `components/extended-metadata-store/src/lib.rs` (and/or `src/flush.rs` for the
  flush-error mapping); no interface change required (`CapacityExhausted` already
  exists).

**Estimated Effort**: small–medium (capacity accounting in the write path).

### Acceptance Criteria
- [ ] An `IExtendedMetadataStore` method constructs and returns
      `ExtendedMetadataStoreError::CapacityExhausted` when region capacity would be
      exceeded.
- [ ] `test_capacity_exhaustion` reaches and asserts the `CapacityExhausted` branch
      (no longer relies on `max_attempts` fallthrough).
- [ ] Previously-written and previously-flushed entries remain retrievable and
      intact after a capacity error (US5 scenario 2).
- [ ] `region_capacity_bytes()` (FR-18) is used for the capacity computation, or an
      equivalent geometry-derived bound.

## Task: Align 001-extended-metadata-store/FR-05 — propagate flush failures through `trigger_flush`  [ALIGN-EMS-003]

**Proposal**: P1 (approved 2026-10-14 by Cornel Constantinescu — "approved as an ALIGN task only: record in align-tasks.md, no code change in this PR")
**Severity**: major

**Spec Requirement**: FR-05 (`spec.md` FR table) and US6 AC1 — `force_flush()` ensures all
mutations are durable, mapping trigger errors to `StorageError`. Interface contract
`components/interfaces/src/iextended_metadata_store.rs:44`: "Returns when all data is durable."

**Current Code**: `force_flush` maps an `Err` from the trigger to `StorageError`
correctly (`src/lib.rs:230-234`), but the documented trigger, `FlushManager::trigger_flush`,
always ends in `Ok(())` (`src/flush.rs:177`). `do_flush` marks the served tickets
complete whether or not `flush_to_disk` failed and discards the error (`src/flush.rs:246-259`).
A device write failure or capacity overflow (`src/flush.rs:36-42`) therefore makes
`force_flush()` return `Ok(())` although nothing new is on disk. No test covers this.

**Status (2026-10-14, branch `fix/bundle-dispatcher-ems`):** RESOLVED by `4a8fe3e7`. `FlushTickets` gained `durable`/`last_error` (`src/flush.rs:88-97`); `trigger_flush` returns `Err(last_error)` unless `durable >= ticket` (`:181-185`). AC1 met (`src/repair_test_force_flush_error.rs:42-61`); AC2/AC3 tracked by proposal P7; AC4 by proposal P1.

**Required Change**:
1. Add `ok_through: u64` and `last_error: Option<String>` to `FlushTickets` (`src/flush.rs:91-94`).
2. In `do_flush`, under the `flush_state` lock: on success `ok_through = max(ok_through, serving)`;
   on failure `last_error = Some(e)`; in both cases `completed = max(completed, serving)`.
   In the `dirty == 0` branch (`:223-231`) also advance `ok_through`.
3. In `trigger_flush`, after the wait (`:172-175`): return `Ok(())` iff `ok_through >= ticket`,
   else `Err(last_error.clone().unwrap_or_default())`.
4. Fix the doc comment at `src/flush.rs:152-153`.
5. Add a `--features testing` fault-injection test.

**Files to Modify**:
- `components/extended-metadata-store/src/flush.rs`
- a new `src/repair_test_*.rs` or `tests/persistence.rs`

**Estimated Effort**: small–medium.

### Acceptance Criteria
- [ ] With `MockBlockDevice::with_fault_config(…, FaultConfig { fail_after_n_writes: Some(0) })`
      and `attach_flush_trigger(Box::new(move || mgr.trigger_flush()))`, `put` then
      `force_flush()` returns `Err(StorageError(_))`.
- [ ] A control case without a fault returns `Ok` and the data is recovered after a reboot.
- [ ] A ticket served by a failed pass but later covered by a successful pass returns `Ok`.

## Task: Align 001-extended-metadata-store/FR-13 — break the trigger ↔ `FlushManager` reference cycle so the final flush runs  [ALIGN-EMS-008]

**Proposal**: P6 (bundle sync; approved 2026-10-18 by Cornel Constantinescu — "approved as an ALIGN task only: record in align-tasks.md, no code change in this PR")
**Severity**: moderate (new finding)

**Spec Requirement**: FR-13 — "`FlushManager` performs a final flush on Drop (graceful shutdown) …"
(`spec.md` FR table). The recommended trigger is `move || flush_manager.trigger_flush()`
(`spec.md` Feature Gating; `src/lib.rs:127`).

**Current Code**: The trigger owns the `FlushManager` (`src/lib.rs:131-133`; field `:61`). The
manager's worker thread owns the callbacks (`src/flush.rs:107-109`, `:142-144`). In every wiring
in the tree, those callbacks capture `Arc<ExtendedMetadataStoreComponent>`
(`src/repair_test_force_flush_error.rs:24`, `:33-37`). The worker exits only after `Drop` sets
`shutdown` (`src/flush.rs:223-227`, `:276-290`). `Drop` runs only when the component's last `Arc`
goes away, and the running worker holds that `Arc`. The result is a reference cycle: no final flush
runs, the worker thread leaks (it polls every 10 ms, `:205`, `:211`), and so does the mock device or
client. No API exists to detach the trigger.

**Required Change** (option 2 is recommended):
1. *Weak callbacks, no API change.* The callbacks capture `Weak<ExtendedMetadataStoreComponent>`.
   `do_flush` must then skip the shutdown pass when the snapshot callback cannot reach the
   component. That needs an `Option<Vec<…>>` sentinel, which is a signature change to
   `FlushManager::start`. Without it, the final pass writes an empty region and loses data.
2. *Explicit detach (recommended).* Add
   `pub fn detach_flush_trigger(&self) -> Option<FlushTrigger>` to
   `ExtendedMetadataStoreComponent`. The wiring layer MUST call it before shutdown and drop the
   result, so `Drop` runs while the component is alive. Update
   `repair_test_force_flush_error.rs` to detach at the end of each test.
- Add a test: attach, `put`, detach + drop, reboot the mock, and assert the entry was recovered.
- After the fix, backfill FR-05/FR-13 in `spec.md` with the detach requirement, and drop the
  "see P6" clause from the FR-13 status cell.

**Files to Modify**:
- `components/extended-metadata-store/src/lib.rs`
- `components/extended-metadata-store/src/repair_test_force_flush_error.rs`
- `components/extended-metadata-store/tests/persistence.rs` (or a new `src/repair_test_*.rs`)
- `specs/001-extended-metadata-store/spec.md` FR-05/FR-13 (backfill after the fix)

**Estimated Effort**: small–medium.

### Acceptance Criteria
- [ ] With a `FlushManager` trigger attached, dropping the component (after detach, if option 2)
      runs the final flush, and the worker thread exits.
- [ ] Test: attach → `put` → shutdown → reboot → `get` returns the value, with no explicit `force_flush()`.
- [ ] The repair tests no longer leak the worker thread.
- [ ] FR-05/FR-13 document the wiring-layer shutdown obligation.
