## Task: Align 001-extended-metadata-store/ALIGN-002 — `force_flush()` durability  [HIGH — FIX DRAFTED]

**Severity**: MAJOR

**Spec Requirement**: FR-05 (001 spec.md) — "`force_flush()` ensures all
mutations are durable on disk"; interface doc comment
(`components/interfaces/src/iextended_metadata_store.rs`) — "Returns when all
data is durable."

**Problem (before)**: `IExtendedMetadataStore::force_flush()` was an
unconditional no-op in every build configuration (default, `testing`, `spdk`)
— `src/lib.rs`. It never called `flush::flush_to_disk` or
`FlushManager::trigger_flush`. A caller holding only the interface received
silent data loss on "flush". Every persistence/SSD test obtained durability by
driving `flush::flush_to_disk()` / `FlushManager::trigger_flush()` directly.

**Change (drafted on branch)** — `components/extended-metadata-store/src/lib.rs`:
- Added a type-erased trigger:
  `pub type FlushTrigger = Box<dyn Fn() -> Result<(), String> + Send + Sync>;`
- Added an optional field `flush_trigger: RwLock<Option<FlushTrigger>>` to the
  `define_component!` fields block (type-erased so the field does not depend on
  the `testing`/`spdk`-gated `FlushManager`).
- Added `attach_flush_trigger(&self, trigger: FlushTrigger)` for the wiring
  layer (which owns the `FlushManager`/`BlockDeviceClient`) to install a
  closure — typically `move || flush_manager.trigger_flush()`.
- Rewrote `force_flush()` to invoke the installed trigger and block until it
  returns, mapping any error to `ExtendedMetadataStoreError::StorageError`; in
  pure in-memory mode (no trigger installed) it remains a correct no-op.

This deliberately keeps `force_flush()` durability an opt-in wired by the layer
that owns the block device, rather than pushing `FlushManager` ownership into
the component — consistent with FR-17's "caller/dispatcher drives durability"
design.

**Files Modified**:

**Estimated Effort**: small (single crate).

## Informational — capacity enforcement (not tasked as a code fix this sweep)

`ExtendedMetadataStoreError::CapacityExhausted` is never constructed; capacity
is enforced only at flush time inside `flush::flush_to_disk` as a `String`
error. The 002 SSD test `test_capacity_exhaustion` loops expecting `put()` to
return a capacity error and so never reaches the exhaustion branch. Per the
user's decision this was resolved by **backfilling the 002 spec** to describe
flush-time capacity enforcement (see 002 spec.md capacity note), rather than
drafting a code change to surface `CapacityExhausted` through the interface.
Surfacing capacity through an interface method remains an option for a future
spec-driven change.
