## Task: Align 002-ssd-integration-test/FR-011 — interface-only usage for durability  [ALIGN-EMS-001]

**Severity**: moderate

**Spec Requirement**: 002 spec FR-011 — "Test MUST use the component's standard
`IExtendedMetadataStore` interface (not internal APIs) for the operations it
validates." Related: 002 FR-007 (persistence) and User Story 3.

**Current Code** (`tests/integration_ssd.rs`): `put`/`get`/`delete`/`iterate_all`
go through the interface, but store creation and durability rely on
inherent/internal APIs — `initialize_from_client` (`:189`), `snapshot_entries`
(`:209`), `extended_metadata_store::flush::flush_to_disk` (`:210`),
`mark_flushed` (`:212`), and `load_entries` (`:432`, `:462`). The durability step
predates FR-05: it was written when `force_flush()` was a no-op. FR-05 is now
implemented (`src/lib.rs:201-215`), so durability can be obtained through the
interface once a `FlushTrigger` is installed via `attach_flush_trigger`.

**Required Change**: In the test's `create_store`/`flush_store` helpers, install a
flush trigger on the component (`comp.attach_flush_trigger(move || flush_manager.trigger_flush())`,
or an equivalent closure that drives `flush::flush_to_disk`) and replace the
direct `snapshot_entries` + `flush_to_disk` + `mark_flushed` durability sequence
with a call to `IExtendedMetadataStore::force_flush()`. Startup recovery via
`initialize_from_client` is an intended FR-17 wiring API and may remain inherent;
narrow FR-011's "operations it validates" to the put/get/delete/iterate_all
operations plus durability. Do **not** modify component source; only the test and
its helpers change.

**Files to Modify**:
- `components/extended-metadata-store/tests/integration_ssd.rs`

**Estimated Effort**: small (single test file + helpers).

### Acceptance Criteria
- [ ] `flush_store` (or equivalent) obtains durability by calling
      `IExtendedMetadataStore::force_flush()`, not `flush::flush_to_disk` directly.
- [ ] A `FlushTrigger` is installed via `attach_flush_trigger` during store setup.
- [ ] `snapshot_entries` / `mark_flushed` are no longer called directly by the test
      for the durability path (they may remain internal to the installed trigger).
- [ ] User Story 3 persistence scenario passes with durability driven through the
      interface on NVMe hardware (`--features spdk`).
- [ ] `initialize_from_client` remains the documented startup-recovery path (FR-17);
      FR-011 note updated to reflect interface-only operation + durability.

## Task: Align 002-ssd-integration-test/FR-007 — surface capacity exhaustion to the caller  [ALIGN-EMS-002]

**Severity**: moderate

**Spec Requirement**: 002 spec FR-007 / User Story 5 scenario 2 / Capacity note —
capacity exhaustion must be surfaced to the caller; `test_capacity_exhaustion`
(`tests/integration_ssd.rs:513-547`) expects an
`ExtendedMetadataStoreError::CapacityExhausted` result. The interface defines the
variant for exactly this purpose (`../interfaces/src/iextended_metadata_store.rs:12`).

**Current Code**: `put()` enforces only the 128 KiB per-value `ValueTooLarge`
limit (`src/lib.rs:159`). Region/partition capacity is enforced solely at flush
time inside `flush::flush_to_disk` as a `String` error ("exceeds region
capacity", `src/flush.rs:32-38`) and is never mapped to
`ExtendedMetadataStoreError::CapacityExhausted` on any interface method.
Consequently `CapacityExhausted` is never constructed and
`test_capacity_exhaustion` loops to `max_attempts` without ever reaching the
`Err(CapacityExhausted)` branch — it passes trivially.

**Required Change**: Surface capacity exhaustion to the caller through the
interface as `CapacityExhausted`. Preferred approach: have `put()` (or a
capacity-aware interface method) detect that the aggregate serialized region
would exceed `Superblock::region_capacity_bytes()` (`src/on_disk.rs:142`) and
return `Err(ExtendedMetadataStoreError::CapacityExhausted)`; alternatively map the
flush-time `String` capacity error to `CapacityExhausted` and propagate it out of
`force_flush()`. Do **not** relax the spec to flush-time-only enforcement. Do
**not** modify source in this sweep — this task is queued for implementation.

**Files to Modify**:
- `components/extended-metadata-store/src/lib.rs` (and/or `src/flush.rs` for the
  flush-error mapping); no interface change required (`CapacityExhausted` already
  exists).

**Estimated Effort**: small–medium (capacity accounting in the write path).

### Acceptance Criteria
- [ ] An `IExtendedMetadataStore` method constructs and returns
      `ExtendedMetadataStoreError::CapacityExhausted` when region capacity would be
      exceeded.
- [ ] `test_capacity_exhaustion` reaches and asserts the `CapacityExhausted` branch
      (no longer relies on `max_attempts` fallthrough).
- [ ] Previously-written and previously-flushed entries remain retrievable and
      intact after a capacity error (US5 scenario 2).
- [ ] `region_capacity_bytes()` (FR-18) is used for the capacity computation, or an
      equivalent geometry-derived bound.
