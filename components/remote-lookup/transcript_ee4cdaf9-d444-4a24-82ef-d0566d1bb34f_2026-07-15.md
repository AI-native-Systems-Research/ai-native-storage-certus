## DPDK vs SPDK

**DPDK** (Data Plane Development Kit) is a userspace framework originally for fast packet processing. Its foundation is the **EAL** (Environment Abstraction Layer), which provides:
- **Hugepage-backed memory management** — it reserves hugepages and hands out memory via `rte_malloc`/`rte_memzone`.
- **NUMA-aware allocation** — you allocate on a specific socket (`rte_malloc_socket(..., socket_id)`), so buffers are local to the core that touches them.
- **Physically-pinned, IOVA-mapped memory** — memory that a device can DMA into/out of (not swappable, stable physical/IO address).
- Poll-mode drivers, lockless rings, per-core mempools.

**SPDK** (Storage Performance Development Kit) is built **on top of DPDK**. It reuses DPDK's EAL wholesale for its environment and memory layer, then adds userspace storage: the NVMe poll-mode driver, the `bdev` block abstraction, etc. Concretely, `spdk_env_init()` initializes DPDK's EAL, and `spdk_dma_malloc()` / `spdk_malloc()` are thin wrappers over DPDK's hugepage allocator. So **SPDK depends on DPDK**; DPDK does not depend on SPDK.
