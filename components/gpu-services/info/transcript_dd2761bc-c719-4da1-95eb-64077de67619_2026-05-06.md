The test validates the end-to-end GPU peer-to-peer DMA path: NVMe SSD reads directly into PyTorch-owned GPU memory via an IPC handle exchange.

## Flow

```
Python (PyTorch)                    Rust (test)
─────────────────                   ───────────────────────────
torch.zeros(N, device='cuda')
cudaIpcGetMemHandle → 64 bytes
base64(handle + size) → stdout  ──→  read payload from child stdout
                                     prepare_memory_for_spdk(payload)
                                       └─ cudaIpcOpenMemHandle (cross-process)
                                       └─ spdk_mem_register (IOMMU map GPU BAR)
                                       └─ DmaBuffer::from_raw(gpu_ptr)
                                     NVMe ReadSync LBA 0 → GPU DmaBuffer
                                     cudaMemcpy D2H → verify pattern
stdin closed  ←─────────────────     drop PyTorchGpuAllocation
```

## Key pieces

**`PYTORCH_IPC_SCRIPT`** — Inline Python that allocates a CUDA tensor via PyTorch, calls `cudaIpcGetMemHandle` through ctypes (stable across PyTorch versions), encodes the 72-byte payload (64-byte handle + 8-byte LE size), prints it, then blocks on `stdin.readline()` to keep the allocation alive.

**`PyTorchGpuAllocation`** — Rust struct that manages the Python child process lifetime. On drop, it writes to the child's stdin causing it to exit, releasing the GPU allocation. This ensures the IPC handle remains valid for the duration of the test.

**`get_context()`** — OnceLock-based hardware initialization (same pattern as `block-device-spdk-nvme` integration tests). Wires up SPDK env, block device, GPU services components. Skips if no GPU, no VFIO, no hugepages, or no NVMe devices. Uses the `atexit(_exit)` trick to bypass SPDK's teardown crash.

**`test_pytorch_ipc_nvme_to_gpu_p2p`**:
1. Writes a known byte pattern to NVMe LBA 0 (standard hugepage DmaBuffer)
2. Spawns Python to get a PyTorch IPC handle for GPU memory
3. `prepare_memory_for_spdk` opens the IPC handle cross-process, registers the GPU memory with SPDK via `spdk_mem_register`, returns a DmaBuffer pointing at GPU device memory
4. NVMe `ReadSync` targets that GPU-backed DmaBuffer — SPDK DMAs from SSD directly into GPU BAR memory (requires nvidia-peermem)
5. `cudaMemcpy` D2H copies GPU contents back to host for assertion

## Why cross-process IPC?

CUDA's `cudaIpcOpenMemHandle` is designed for inter-process sharing — calling it in the same process that exported the handle fails with "invalid device context" on most drivers. By having Python allocate the tensor in a separate process, the Rust side can legitimately open the handle. This mirrors the real production scenario: a PyTorch inference server passes GPU memory handles over gRPC to the storage service.

## Hardware requirements

- NVIDIA GPU with PyTorch+CUDA installed
- SPDK-bound NVMe device (VFIO + hugepages)
- `nvidia-peermem` kernel module loaded (for `spdk_mem_register` to map GPU BAR memory through IOMMU)

If nvidia-peermem isn't loaded, `spdk_mem_register` returns -EINVAL and the test skips gracefully after confirming the IPC exchange itself works.
