## Task: Align 001-block-device-filesys/telemetry-latency

**Severity**: major

**Spec Requirement**: FR-019 (backfilled) / Assumptions — telemetry MUST report real per-operation latency (min/max/mean, in ns) computed from actual op start/finish timestamps.

**Current Code**: Every call site passes a hard-coded latency of `0` into `record_op(0, bytes)` — both sync and async paths, and in `harvest_completions` — so `min_latency_ns`/`max_latency_ns`/`mean_latency_ns` in `TelemetrySnapshot` are always 0 regardless of real IO latency. `InflightOp.start_ns` is computed as `Instant::now().elapsed().as_nanos()` (elapsed() on a freshly-created `Instant` is ~0) and is never read when a completion is harvested. By contrast, `block-device-spdk-nvme` measures real per-op latency via TSC timestamps (`components/block-device-spdk-nvme/src/actor.rs:613,636`).

**Required Change**: Capture a real submission timestamp (e.g., `Instant::now()` at the point the op is submitted, or a TSC read to mirror block-device-spdk-nvme) and compute actual elapsed time at completion (sync path: around the `pread`/`pwrite`+`fdatasync` call; async path: at CQE harvest using the stored start time), then pass that real value into `record_op`.

**Files to Modify**: `components/block-device-filesys/src/actor.rs` (lines ~101-104, 318-321, 379-382, 462-466, 494-497, 585-589, 627-630, 773-776 per drift report), `components/block-device-filesys/src/telemetry.rs` (if the collector's API needs adjusting to accept a start/end pair instead of a precomputed delta).

## Task: Align 001-block-device-filesys/io-uring-backpressure

**Severity**: major

**Spec Requirement**: Edge Cases — "What happens when io_uring submission queue is full? The actor MUST back-pressure by waiting for completions before submitting new operations."

**Current Code**: There is no backpressure/wait logic anywhere in the actor. On SQE push failure (`handle_read_async`, `handle_write_async`), the actor immediately returns an error `Completion` (`NvmeBlockError::NotInitialized("io_uring submission queue full")`) to the client rather than waiting for ring space and retrying submission.

**Required Change**: Add a pending-submission queue (mirroring the `ClientSession::pending`/`flush_pending` FIFO backlog pattern already used for completion delivery) that buffers a command whose SQE push failed, and retries submission from that queue each time `on_idle()` observes free ring space (e.g., after harvesting CQEs), instead of failing the operation immediately.

**Files to Modify**: `components/block-device-filesys/src/actor.rs` (`handle_read_async` ~430-444, `handle_write_async` ~546-561, and the `on_idle()` event loop ~876-908).
