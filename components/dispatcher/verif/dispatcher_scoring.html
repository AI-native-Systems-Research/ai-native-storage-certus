How to read this page

The result above is at the level of individual properties. A property is one precise, checkable claim about how the component behaves (for example: every emitted log line ends with a single newline). This component has 170 such verifiable properties, and 110 of them carry a machine-checked proof from Creusot and/or Kani; 0 are soundly delegated to a named external tool, and 60 are left open.

“Proved” means a tool proved the property itself. Each tool's scorer re-runs that tool's own artifact from source and checks it passes — Creusot: cargo creusot reports every goal Proved; Kani: cargo kani reports VERIFICATION SUCCESSFUL with the anti-vacuity __mutant twin going RED.

The two tools are complementary, so their individual counts differ and neither alone covers everything. Where one tool cannot even state a property (e.g. Creusot's logic model treats string contents as opaque), the other tool proves it — that is a sound hand-off, not a gap. The per-method tables further down group properties by the method they constrain; there B is simply the number of properties in that group (the “bundle size”), and proved / B is how many of them that one tool proves by itself.

What these times include. Each figure is the sum of the first proof attempt per property, as measured by the scorer around one whole toolchain invocation (/usr/bin/time -v cargo kani --harness <h> or cargo creusot <module>). So it is build + proof, not solver time: a sub-second proof still shows seconds because compilation is counted with it, and Kani re-invokes the toolchain per harness while Creusot's runs are largely incremental — which is most of why Kani's per-property figures sit well above Creusot's. A figure at or near the cap (--cap-seconds, escalating once to --cap-max) is a timeout, not solving.
What they exclude. The scorer also runs an anti-vacuity __mutant twin for each proved property and the full lever battery for each tool-boundary; those invocations are not counted here, so one property can cost 2–5 runs while only the first is timed. Total machine cost per tool is the stage wall-clock in verif/.run/<stage>.done, which is larger than the sum above. Peak RSS is the largest single timed run, not a total. Agent time to author the proofs is not measured anywhere on this page.
