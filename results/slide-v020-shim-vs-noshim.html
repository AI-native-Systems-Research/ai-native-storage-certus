Round time grows with the re-read prefix. Compat measured from log timestamps; non-shim per-round wasn't logged — its 99.0 s/round mean shown for scale.

Read the two together: per-round read GiB and read latency are essentially identical across the two connectors, so the workload is the same — yet the non-shim build finishes 122.6 s sooner. The capability-matrix shim (per-call Python dict lookup) is not a plausible ~10% wall mover; the gap is host/tier-side, not connector overhead.

  • Not a back-to-back A/B. Runs are 9 days apart with intervening host changes (fs move, hugepage-NUMA fix). Treat as "no evidence the shim costs I/O," not a controlled 10% claim.
  • Tier size differs. Non-shim 13.0 GiB (from server.log); compat ~12 GiB (run notes). A smaller tier demotes more → most of compat's +5.3% write.
  • Non-shim per-round wall not captured. Engine stats were disabled; only the 1188.5 s total exists → 99.0 s/round mean. Compat per-round reconstructed from timestamps (±few s).
  • Everything else held equal. Same 5,400 gens, same model/params, same 60% evict threshold; per-round SSD counters read directly from each run's connector log.
