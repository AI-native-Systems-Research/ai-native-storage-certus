# Running the OTel replay on the cc131k mooncake trace

Notes for driving the `kv-offload-otel-replay` harness against the **cc131k**
trace (`/mnt/certus1/cc-traces-weka-062126.mooncake-131k.jsonl`, Qwen2.5, 131K
window). The `cc131k-step*.sh` scripts wrap the generic `run-docker-otel-*.sh`
arms with cc131k-appropriate defaults; every value below is env-overridable.

cc131k is a flat **mooncake** request log (one request per line: `timestamp`,
`input_length`, `output_length`, `hash_ids`), not an OTel corpus — so step 1
reconstructs conversations from the `hash_ids` prefix chains, and step 2
materialises the OTel corpus the arms replay.

## The pipeline

| Step | Script | What it does |
|------|--------|--------------|
| 0 | `cc131k-step0-build.sh` | build `certus-server-yaml` (`--features spdk`, `CERTUS_PROFILE=full-optimized`) — only needed for the `shmq` arm |
| 1 | `cc131k-step1-reconstruct.sh` | mooncake JSONL → plan trace (`trace-gen/mooncake_to_plan.py`) |
| 2 | `cc131k-step2-corpus.sh` | plan → per-conversation OTel corpus (`trace-gen/trace_to_otel.py`) |
| 3 | `cc131k-step3-server.sh` | start the host `certus-server-yaml` shmq mailbox (foreground; `shmq` arm only) |
| 4 | `cc131k-step4-run.sh` | replay the corpus against one backend |

### Quick start (Certus-SHMQ, single A100)

```bash
cd benchmarks/kv-offload-otel-replay
./cc131k-step0-build.sh                      # once (and after a branch switch)
./cc131k-step1-reconstruct.sh                # ~7s, writes the plan
./cc131k-step2-corpus.sh                     # builds the corpus; prints du -sh + max span
bash build-otel.sh                           # one-time: VLLM_VERSION=0.29.0 ONLY=shmq ./build-otel.sh
./cc131k-step3-server.sh                     # in its own shell/tmux (holds the terminal)
ARM=shmq ./cc131k-step4-run.sh               # in another shell
```

Other arms are self-contained (no step 3):
```bash
ARM=offload   ./cc131k-step4-run.sh          # CPUOffload
ARM=nooffload ./cc131k-step4-run.sh          # NoOffload baseline
ARM=cputier   FS_TIER_HOST=/mnt/certus1/kv-fs-tier ./cc131k-step4-run.sh
```

## Prerequisites

- NVMe bound to vfio-pci + 1 GiB hugepages (`sudo tools/configure-bench.sh`) — for the `shmq` server.
- Replay images in the `/mnt/certus1` podman store: `VLLM_VERSION=0.29.0 ./build-otel.sh`.
- `certus-server-yaml` built: `./cc131k-step0-build.sh`.

## Key parameters (step 4)

Defaults in parentheses; all overridable via env.

### Model / placement — **Option A: single A100-40G**
| Env | Default | Notes |
|-----|---------|-------|
| `MODEL` | `Qwen/Qwen2.5-7B-Instruct` | 7B fits one 40 GB card; 14B needs TP=2. 7B/14B share the tokenizer, so the corpus is reusable |
| `TENSOR_PARALLEL_SIZE` | `1` | set `2` + `GPU=all` for the 14B two-GPU config |
| `GPU` | `0` | pin to one A100; `all` exposes both |
| `OTEL_HOST` | `/mnt/certus1/inference-perf-syn-data/otel_cc131k` | corpus dir from step 2 |
| `NUM_CONVS` | `200` | up to 2612 (bounded because corpus size grows fast) |

### Concurrency — **how many sessions run, and which next**
| Env | Default | Notes |
|-----|---------|-------|
| `ACTIVE_SESSIONS` | `0` | **max concurrent sessions.** `0` = open loop (offer all; vLLM runs `MAX_NUM_SEQS` at a time); `N` = closed loop, at most N conversations in flight |
| `MAX_NUM_SEQS` | `64` | vLLM running-batch cap |
| `ADMIT_ORDER` | `sequential` | closed-loop session-selection policy (only when `ACTIVE_SESSIONS>0`). `sequential` = next by ascending index; `random` = uniform pick from the arrival-gated ready set. **No round-robin option.** |
| `ADMIT_SEED` | _(unset)_ | seeds `random` admission; unset = nondeterministic draw. Forwarded only when set |
| `TIME_SCALE` | `0` | `0` = saturating (ignore recorded timing); `1.0` = honor the mooncake inter-turn cadence (long!); `0.1` = 10× compressed |

> The admission policy only matters in **closed loop**. In open loop
> (`ACTIVE_SESSIONS=0`) there is no admission order — vLLM's own scheduler picks
> which of the flooded requests run, bounded by `MAX_NUM_SEQS`.

### Metrics (Grafana)
| Env | Default | Notes |
|-----|---------|-------|
| `PROM` | `1` | `1` = `-prom` arm (metrics on); `0` = no metrics |
| `PROM_PORT` | `8000` | scrape target: `http://127.0.0.1:${PROM_PORT}/metrics` — **IPv4 only** (podman), use `127.0.0.1`, not `localhost` |
| `LOG_STATS` | `1` | registers vLLM's PrometheusStatLogger |

These are the **client-side** vLLM + KV-offload metrics (prefix-cache hits,
offload stores/loads, throughput). The SPDK/SSD-side server counters are separate
and not a Prometheus endpoint.

### Arm-specific
| Arm | Env | Default |
|-----|-----|---------|
| `shmq` | `SHM_PATH` / `SLAB_SIZE_BYTES` | `/dev/shm/certus-shmq` / `2097152` (must match step 3) |
| `cputier` | `FS_TIER_HOST` / `CPU_BYTES` | `/mnt/certus1/kv-fs-tier` / `13 GiB` |
| any | `EXTERNAL_HITS=1` | shrinks `GPU_MEM_UTIL`→`0.55` to force offload-tier reloads (drive `vllm_external_prefix_cache_hits_total`) |

## Step 3 server defaults

`certus-server-yaml`, 4 NVMe (`0000:61..64:00.0`), `MEMORY_TIER_SIZE=32G`,
`EVICTION_THRESHOLD=0.9`, `CHANNELS=32`, `SHM_PATH=/dev/shm/certus-shmq`, NUMA 0.

> **vLLM 0.29:** use `CHANNELS=64`. The 0.29 LBHNC KV layout exhausts 32 channels
> under concurrent load (RingError/EngineDeadError); 0.26–0.28 are clean at 32.

## Step 1 / corpus options

| Env (step 1) | Default | Notes |
|--------------|---------|-------|
| `SHARED_PREFIX` | `0` | inject a synthetic N-token system prefix reused by every conversation → drives cross-conversation external-cache hits (the real trace has ~none) |
| `ZERO_LATENCY` | `0` | `1` emits 0 inter-turn latency (old saturating plan); default carries the mooncake timestamps as per-turn gaps |
| `MAX_ROWS` / `STATS_ONLY` | _(all)_ / `0` | quick-test knobs |

step 2: `CAP=120000` (accounted-prompt cap, < 131072 window), `SEED=7`,
`VALIDATE=1`. The adapter also clamps `output_length==0 → 1` and per-turn input
to `--max-input=120000`.

## Fidelity caveats

- Reconstruction yields ~2612 conversations from 13,413 rows; **706 branch roots**
  lose cross-conversation prefix sharing (`trace_to_otel` models only one global
  prefix), and ~1937 turns have their incremental input clamped to 1 (real
  context compaction in the trace).
- Timestamps are **global request-arrival** times attributed to reconstructed
  chains, so a within-chain gap is real wall-clock between requests (includes the
  original generation time, not pure think-time). Total ≈322 h of recorded cadence.
- `vllm_external_prefix_cache_hits_total = 0` is expected on the raw trace:
  within-conversation reuse is served from the on-GPU prefix cache, and there's
  little cross-conversation reuse. Use `SHARED_PREFIX` and/or `EXTERNAL_HITS=1`
  (and `TIME_SCALE=1.0`) to actually exercise the offload read path.
- Validated end-to-end on **vLLM 0.29**; the original `max_tokens=0` crash was the
  `output_length==0` rows (now clamped), and a `_build_store_jobs` assert seen on
  **0.26** is the known 0.26 tiering bug (use 0.29).

## Example runs

```bash
# Closed loop, 80 concurrent sessions, random admission (seeded), metrics on :9100
ACTIVE_SESSIONS=80 ADMIT_ORDER=random ADMIT_SEED=42 PROM_PORT=9100 \
  ARM=shmq ./cc131k-step4-run.sh

# Honor recorded multi-day cadence (long run), 40 concurrent sessions
TIME_SCALE=1.0 ACTIVE_SESSIONS=40 ARM=shmq ./cc131k-step4-run.sh

# Drive external-cache hits: synthetic shared prefix + eviction pressure
SHARED_PREFIX=8192 PLAN=/mnt/certus1/inference-perf-syn-data/cc131k-sp8k.plan.json \
  ./cc131k-step1-reconstruct.sh
PLAN=/mnt/certus1/inference-perf-syn-data/cc131k-sp8k.plan.json \
  OTEL_HOST=/mnt/certus1/inference-perf-syn-data/otel_cc131k_sp8k ./cc131k-step2-corpus.sh
OTEL_HOST=/mnt/certus1/inference-perf-syn-data/otel_cc131k_sp8k \
  ARM=shmq EXTERNAL_HITS=1 ./cc131k-step4-run.sh

# 14B across two GPUs
MODEL=Qwen/Qwen2.5-14B-Instruct TENSOR_PARALLEL_SIZE=2 GPU=all CHANNELS=64 \
  ARM=shmq ./cc131k-step4-run.sh
```
