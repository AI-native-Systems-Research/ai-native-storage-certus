## Task: Align 001-rdma-network-test/FR-012

**Severity**: Major

**Spec Requirement**: `spec.md` FR-012 and Edge Cases: "System MUST retry
failed RDMA connections up to 3 times before aborting, and report partial
results if any measurements were collected before failure." (Clarified in
the 2026-06-05 session: "Retry connection up to 3 times, then abort and
report partial results collected before failure.")

**Current Code**:
- The only 3x-retry loop in the codebase, `poll_completion_with_retry`
  (`src/rdma.rs:226-237`), wraps a single completion-queue poll for one
  work request. It does not retry RDMA-CM connection establishment.
- `client_connect` (`src/rdma.rs:331`) and `server_connect`
  (`src/rdma.rs:433`) each call `rdma_resolve_addr` / `rdma_resolve_route`
  / `rdma_connect` / `rdma_accept` exactly once, with no retry or backoff
  if the handshake itself fails.
- `TestOutput.partial` is hard-coded to `false` in `src/client.rs:129` and
  is never set to `true` anywhere in the codebase.
- On any mid-test error, `main()` (`src/main.rs:262-265`) prints the
  `anyhow` error to stderr via `eprintln!("Error: {:#}", e)` and calls
  `process::exit(1)` — no `TestOutput` (JSON or human-readable) carrying
  whatever partial measurements were collected is ever constructed or
  printed.
- `tasks.md` currently marks T032 ("Implement partial results reporting")
  as complete (`[X]`); this checkbox is inaccurate relative to the actual
  code and should be revisited once this task is implemented.

**Required Change**:
1. Wrap the connection-establishment sequence in `client_connect` /
   `server_connect` (`src/rdma.rs`) in a bounded retry loop (reuse the
   existing `MAX_RETRIES = 3` constant / equivalent), with a reasonable
   backoff, so that a transient RDMA-CM handshake failure is retried up to
   3 times before the connection attempt is treated as failed.
2. Thread whatever `ThroughputStats` / `LatencyStats` have already been
   collected (e.g., during `--test all`, results from test kinds that
   completed before a later kind failed) through the error path in
   `main()` / `client::run()`, and construct a `TestOutput` with
   `partial: true` and `error: Some(<description>)` populated with the
   partial results, printed via the existing `output::print_json` /
   human-readable path, instead of only `eprintln!`-ing the error.
3. Re-open and complete `tasks.md` T032 once implemented (currently marked
   `[X]` but not reflected in code).
4. Alternatively, if connection-level retry is intentionally out of scope
   and only per-operation completion retry is desired, relax FR-012's
   wording accordingly in a follow-up spec-sync pass — do not silently
   narrow the spec as part of this backfill.
