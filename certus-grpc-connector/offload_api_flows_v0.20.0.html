Certus gRPC Offload Connector — API Call Flows

vLLM OffloadingConnector → certus-server, mapped onto u64-keyed batch gRPC
vllm==0.20.0 · OffloadingSpec
Manager = scheduler role · Handlers = worker role

STORE flow

GPU KV blocks  ──▶  Certus DRAM / NVMe
1 prepare_store(keys)Manager · scheduler
Check(BatchCheckRequest) then Reserve(BatchReserveRequest)
Check filters already-cached keys; Reserve allocates a DRAM slot per key (server evicts LRU to fit). Best-effort: keep keys that reserved, drop the rest — never reject the whole batch.
2 transfer_async(spec)GpuToCertusHandler · worker
CopyToStore(BatchCopyToStoreRequest)
Per block, share the KV-cache CUDA IPC handle + byte offset = block_id × stride; server DMAs D2H at open(handle)+offset. Async future, reaped by get_finished().
3 complete_store(keys, success)Manager
CommitStore(success) / AbortStore(failure)
Split-phase Reserve→Copy→Commit. A failed CopyToStore still reports success to vLLM (worker asserts it) but AbortStore rolls back that key so Commit can't publish an empty slot.

LOAD flow

Certus DRAM / NVMe  ──▶  GPU KV blocks
1 lookup(key)Manager · scheduler
Check(BatchCheckRequest)
Hit test on the remote index — decides whether the block is served from Certus instead of recomputed.
2 prepare_load(keys)Manager
Pin(promote=false)
Takes an eviction-protecting read-ref only. promote=false is critical: Lookup (next step) promotes cold entries itself — a second promote races and hits AlreadyExists, failing the load.
3 transfer_async(spec)CertusToGpuHandler · worker
Lookup(BatchLookupRequest)
Same IPC-handle + offset mechanism, reversed: server DMAs H2D into each GPU block. Serves DRAM hits directly, promotes NVMe (cold) misses in one path.
4 complete_load(keys)Manager
Unpin(BatchUnpinRequest)
Releases the read-ref, making the block evictable again once the copy into GPU memory has landed.
